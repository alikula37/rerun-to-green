The question

Every developer knows the reflex: “CI is red. My diff looks fine. Let me just rerun it.”

How often does that actually work? We measured it on public data — no estimates.

The number

All failed runs (red)~28% turned green on a same-commit rerun

And the press-rerun case, validated on a random sample: ~75% of runs that were re-run on a failed first attempt finished green.

How we measured

  1. Downloaded workflow-run metadata for 32 public repos via the GitHub API.
  2. Grouped runs by (repository, workflow, commit SHA).
  3. Found episodes that started red (failure / timed_out).
  4. Checked whether a later run of the exact same commit finished green.
  5. Validated the press-rerun case on a random sample (attempt #1 fetched and confirmed as a genuine failure).

No source code. No logs. No user data. Public metadata only.

What this does and does not mean
  • Green after rerun ≠ code is correct. It means the failure wasn't caused by your commit in that run.
  • This is not “AI causes this”. We don't know which runs were AI-written and we don't claim to.
  • Selection bias: developers re-run runs they suspect are flaky, so ~75% is conditional on choosing to rerun.
  • Snapshot: 2026, up to 90 days, 32 curated repos; heavy repos capped at 6,000 most recent runs.
The point

AI coding tools are measured by how fast a patch is written. But a patch isn't done when it's written — it's done when CI is green.

AI writes the patch. CI decides whether it's usable.
